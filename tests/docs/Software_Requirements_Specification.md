Project: 지하철 부정승차 방지 시스템 (SFEPS)  
Version: 1.2  
Date: 2026-03-03  
Author: 서형철  

---

## 1. 개요
### 1.1 목적
본 문서는 SFEPS의 기능/비기능 요구사항을 정의한다. 본 요구사항은 테스트 계획, 테스트 조건, 테스트케이스 작성 및 추적성(Traceability Matrix) 수립의 기준이 된다.

### 1.2 시스템 목표
- 지하철 개찰구에서 발생하는 **부정승차 의심 상황을 1차 자동 판정**하여 관리자에게 이벤트로 제공한다.
- 관리자가 **2차 육안 검증(얼굴 스크린샷 + 카드 정보)** 후, 확실하다고 판단한 경우에만 **Tracking(레이저)**을 수동으로 실행한다.

### 1.3 용어 정의
- **QT Client**: 관리자 UI(Windows 11)
- **Server**: Raspberry Pi 기반 API/중계 서버(이벤트 처리/API 제공)
- **Camera**: PNO-A9081R (영상 입력)
- **STM32**: Nucleo F401RE (레이저 모듈 제어용)
- **의심 이벤트(Suspicious Event)**: 1차 자동 판정 결과로 생성되어 Client에 표시되는 이벤트 로그
- **Tracking**: 관리자의 명시적 버튼 클릭으로 수행되는 레이저 추적 동작

---

## 2. 시스템 구성/아키텍처 요구 (System Architecture Requirements)

### REQ-ARCH-001 구성 요소
시스템은 다음 구성 요소로 이루어져야 한다.
- Camera(PNO-A9081R)
- Raspberry Pi(Server)
- QT Client(관리자 인터페이스)
- STM32(Nucleo F401RE, 레이저 제어)

### REQ-ARCH-002 영상/이벤트 데이터 흐름
- 영상 스트리밍은 **Camera → Server → QT Client** 경로로 제공되어야 한다.
- 1차 자동 판정 결과(의심 이벤트)는 **Server → QT Client**로 전달되어야 한다.

### REQ-ARCH-003 Tracking 제어 흐름(관리자 수동)
Tracking 제어는 다음 흐름으로 수행되어야 한다.
- QT Client(관리자) → Server
- Server → STM32 → 레이저 모듈 제어

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 로그인
#### REQ-FUNC-LOGIN-001 로그인
사용자는 QT Client에서 ID와 PW를 입력하여 로그인할 수 있어야 한다.

#### REQ-FUNC-LOGIN-002 로그인 실패 처리
ID가 존재하지 않거나 PW가 올바르지 않은 경우 로그인은 실패해야 하며, 오류 메시지를 표시해야 한다.

#### REQ-FUNC-LOGIN-003 필수 입력값 검증
ID 또는 PW가 공백(미입력 포함)인 경우 로그인은 실패해야 하며, 사용자에게 안내해야 한다.

---

### 3.2 영상 스트리밍
#### REQ-FUNC-STREAM-001 영상 수신/표시
QT Client는 Server를 통해 Camera 영상 스트림을 수신하여 화면에 표시해야 한다.

#### REQ-FUNC-STREAM-002 스트리밍 오류 표시
네트워크 단절 등으로 스트리밍 수신이 불가할 경우 QT Client는 오류 상태를 표시해야 한다.

#### REQ-FUNC-STREAM-003 스트리밍 자동 재연결
네트워크가 복구되면 스트리밍은 자동으로 재연결/복구되어야 한다(재시도 정책은 구현에 따름).

---

### 3.3 의심 판정 및 이벤트 생성(1차 자동)
> 얼굴 추정 나이 알고리즘은 미구현이므로, 테스트에서는 Mock 값 입력/생성이 가능해야 한다.

#### REQ-FUNC-EVENT-001 무태그 기반 의심 판정
무태그(카드 정보 없음)인 경우 시스템은 부정승차(의심)로 판정할 수 있어야 한다.

#### REQ-FUNC-EVENT-002 우대카드 의심 판정(나이 규칙)
우대카드(청소년/노인)인 경우, 시스템은 우대카드 연령 규칙과 얼굴 추정 나이(또는 Mock age)를 비교하여 의심 여부를 판정해야 한다.
- 청소년 우대카드: age < 20 정상, age ≥ 20 의심
- 노인 우대카드: age < 60 의심, age ≥ 60 정상

#### REQ-FUNC-EVENT-003 의심 이벤트 생성
1차 판정 결과가 의심인 경우 시스템은 의심 이벤트 로그를 생성해야 한다.

#### REQ-FUNC-EVENT-004 정상 시 이벤트 미생성
1차 판정 결과가 정상인 경우 의심 이벤트는 생성되지 않아야 한다.

#### REQ-FUNC-EVENT-005 비정상 이벤트 메시지 포맷 처리
시스템(Server 및 QT Client)은 이벤트 메시지를 수신할 때, 필수 필드 누락, 필드 타입 불일치, 파싱 불가능한(깨진) 메시지 등 비정상 포맷이 포함된 경우에도 크래시/프리징 없이 해당 메시지를 무시하거나 실패 처리해야 한다. 또한 비정상 메시지 처리 이후에도 시스템은 정상 이벤트 메시지를 계속 처리할 수 있어야 한다.

---

### 3.4 이벤트 UI(목록/상세)
#### REQ-FUNC-UI-001 이벤트 목록 표시
Server는 의심 이벤트를 QT Client로 전달해야 하며, QT Client는 이벤트 로그 목록에 표시해야 한다.

#### REQ-FUNC-UI-002 이벤트 상세 팝업 표시
관리자가 특정 이벤트를 선택하면 QT Client는 이벤트 상세 팝업(Detail View)을 표시해야 하며, 다음 정보를 제공해야 한다.

- 얼굴 스크린샷(또는 캡처 프레임)
- 카드 정보
- 추정 나이(Mock 포함)
- 발생 시각/게이트 ID

#### REQ-FUNC-UI-003 로그아웃 처리
관리자가 로그아웃 버튼을 클릭하면 QT Client는 서버로 로그아웃 요청을 전송해야 하며, 현재 세션을 종료하고 로그인 화면으로 복귀해야 한다.

---

### 3.5 Tracking(레이저) — 관리자 수동 트리거
#### REQ-FUNC-TRACK-001 관리자 수동 실행 조건
Tracking(레이저)은 **관리자가 스트리밍 객체 바운딩박스의 Track 버튼을 클릭한 경우에만** 수행되어야 한다.

#### REQ-FUNC-TRACK-002 레이저 트래킹 제어
Tracking 시작 시 Server는 STM32에 레이저 트래킹 ON 명령을 전달해야 하며, 종료 시 OFF 명령을 전달해야 한다.

#### REQ-FUNC-TRACK-003 Tracking 상태 표시
QT Client는 Tracking의 ON/OFF 상태를 UI에 표시해야 한다.

---

### 3.6 네트워크(연결 상태 표시)
#### REQ-FUNC-NET-001 연결 상태 표시
QT Client는 Server 연결 상태(연결/단절/재연결)를 표시할 수 있어야 한다.

---

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능(Performance)
#### REQ-NF-PERF-001 Tracking 제어 응답 시간(레이저)
관리자가 스트리밍 객체 바운딩박스의 Track 버튼 클릭 시점부터 **레이저 트래킹 ON ACK(또는 처리완료 확인)**까지 **1초 이내**여야 한다.

#### REQ-NF-PERF-002 이벤트 처리량
시스템은 1분 내 50건 이상의 의심 이벤트를 처리(생성/전달/표시)할 수 있어야 한다.

---

### 4.2 신뢰성(Reliability)
#### REQ-NF-RELI-001 Tracking 반복 안정성(레이저)
의심 이벤트가 존재하는 상태에서 관리자가 스트리밍 객체 바운딩박스를 통해 Tracking(ON→OFF/종료)을 20회 반복 수행해도
- 오류/예외/비정상 종료가 없어야 하며
- UI 표시와 실제 레이저 동작 간 상태 불일치가 없어야 한다.

#### REQ-NF-RELI-002 스트리밍 연속성
시스템은 1시간 연속 스트리밍을 유지할 수 있어야 한다(중단 시 자동 복구 정책 적용 가능).

---

### 4.3 회복성(Recoverability)
#### REQ-NF-REC-001 네트워크 단절 후 복구
네트워크 단절이 5초를 초과하면 QT Client는 자동 로그아웃되어 로그인 화면으로 전환되어야 하며, 연결 복구 후 재로그인 시 시스템은 정상 동작 상태로 복귀해야 한다.

---

## 5. 제약사항 및 가정(Assumptions)
- 얼굴 추정 나이 알고리즘 정확도는 테스트 범위에서 제외하며, 테스트에서는 Mock age 사용을 허용한다.
- 하드웨어 물리 정밀도(레이저 조준 정확도 등) 인증은 범위에서 제외한다.

---

## 6. 추적성(Traceability) 가이드
- 테스트 조건/케이스는 상위 요구사항 ID(REQ-*)를 참조해야 한다.  
  예) Tracking 버튼 클릭 → 1초 이내 동작 검증은 `REQ-NF-PERF-001`, `REQ-FUNC-TRACK-001~002`에 매핑한다.
