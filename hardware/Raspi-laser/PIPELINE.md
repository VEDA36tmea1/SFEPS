# Raspi-laser ↔ Ubuntu 파이프라인 (오차 수신 + 50Hz PID/PWM)

호스트(host_cpp) + Ubuntu TCP 서버 파이프라인에서 **레이저–바운딩박스 오차**를 보내고,  
**라즈베리 파이**가 이를 수신해 **50Hz(20ms) 주기로 PID 제어 후 PWM**으로 출력하는 구성입니다.

---

## 1. 데이터 흐름

```text
[RTSP/카메라] → rtsp_laser_demo (e_u, e_v stdout)
       ↓
  ubuntu_tcp_server (stdin → "EX=float,EY=float\n" TCP 전송)
       ↓
  라즈베리 파이 pid_pwm_agent.py (TCP 클라이언트, 50Hz PID → pwm0/pwm1)
       ↓
  GPIO12(pwm0)=X, GPIO13(pwm1)=Y → 서보/레이저 구동
```

- **오차**: 픽셀 단위 `e_u`(타겟.x - 레이저.x), `e_v`(타겟.y - 레이저.y)
- **Ubuntu 서버**: `EX=...,EY=...\n` 한 줄씩 TCP로 전송 (기본 포트 5555)
- **제어 주기**: 20ms(50Hz). 모터/서보 주기와 동일하게 맞춤.

---

## 2. Ubuntu 쪽 실행 (노트북)

### 2.1 TCP 서버만 띄우고 수동 입력으로 테스트

```bash
cd hardware/stm32-laser/tmp_server/ubuntu_server
make ubuntu_tcp_server   # 필요 시
./ubuntu_tcp_server      # 기본 0.0.0.0:5555
```

- 터미널에서 `10.5 -20.3` 처럼 **두 실수** 입력 시 → 클라이언트(라즈베리)로 `EX=10.500000,EY=-20.300000\n` 전송됨.

### 2.2 host_cpp 파이프라인으로 오차 자동 전송

```bash
# rtsp_laser_demo가 stdout으로 "e_u e_v" 출력 → ubuntu_tcp_server stdin으로 파이프
./rtsp_laser_demo "rtsp://..." 2>/dev/null | ./ubuntu_tcp_server 5555
```

- RTSP URL은 실제 카메라/스트림으로 교체.
- `rtsp_laser_demo`는 박스+레이저가 모두 있을 때만 `e_u e_v` 를 stdout으로 보냄.

---

## 3. 라즈베리 파이 쪽 실행

### 3.1 PWM 사전 설정 (한 번만, config.txt + export)

- `config.txt` 에 `dtoverlay=pwm-2chan,pin=12,func=4,pin2=13,func2=4` 적용 후 재부팅.
- 필요 시 수동 export:
  ```bash
  echo 0 | sudo tee /sys/class/pwm/pwmchip0/export
  echo 1 | sudo tee /sys/class/pwm/pwmchip0/export
  ```

### 3.2 PID+PWM 에이전트 실행

- Ubuntu 노트북 AP에 라즈베리 연결 후, **노트북 IP**를 `--host`에 지정 (예: `10.42.0.1`).

```bash
cd hardware/Raspi-laser

# 기본: host 10.42.0.1, port 5555, 초기 PWM x=1530µs, y=1300µs
sudo python3 pid_pwm_agent.py --host 10.42.0.1 --port 5555

# 게인만 변경
sudo python3 pid_pwm_agent.py --host 10.42.0.1 --kp-x 0.02 --kp-y -0.02

# PWM 미쓰고 수신만 확인 (dry run)
python3 pid_pwm_agent.py --host 10.42.0.1 --no-pwm
```

- **sudo**: sysfs PWM 쓰기 권한 때문에 필요.
- 에이전트는 TCP로 계속 오차를 받아 20ms마다 PID 출력을 pwm0/pwm1 `duty_cycle`에 반영합니다.

## 5. 오차 계산 — 서버가 보내는 값

`rtsp_laser_demo.cpp`에서 카메라 프레임마다 계산:

```
e_u = target_center.x − laser_point.x   (수평 픽셀 오차)
e_v = target_center.y − laser_point.y   (수직 픽셀 오차)
```

```text
  ┌────────────────────────────────────┐
  │            카메라 화면               │
  │                                    │
  │     ╔══════╗                       │
  │     ║ 타겟  ║ center=(500, 400)     │
  │     ║ bbox ║──────┐                │
  │     ╚══════╝      │ e_v = 400−350  │
  │                   │    = +50       │
  │            ● laser=(530, 350)      │
  │            │                       │
  │            └── e_u = 500−530 = −30 │
  └────────────────────────────────────┘
```

| 부호 | 뜻 | 서보가 해야 할 일 |
|------|-----|-------------------|
| `e_u > 0` | 레이저가 타겟보다 **왼쪽** | PWM 증가 → 서보 오른쪽 |
| `e_u < 0` | 레이저가 타겟보다 **오른쪽** | PWM 감소 → 서보 왼쪽 |
| `e_v > 0` | 레이저가 타겟보다 **위** | Kp_y 부호에 따라 결정 |
| `e_v < 0` | 레이저가 타겟보다 **아래** | Kp_y 부호에 따라 결정 |

`ubuntu_tcp_server.cpp`는 이 값을 그대로 `EX=...,EY=...\n` 포맷으로 래핑해서
TCP 전송할 뿐, **값 자체의 변환은 없다.**

## 6. PID 계산식 상세 (위치형 PID)

### 6.1 왜 위치형 PID인가

서보 모터는 **위치 액추에이터**다.
PWM 1530µs를 주면 해당 각도로 가고, 1600µs를 주면 다른 각도로 간다.
서보 자체가 누적하지 않고, 주어진 PWM에 대응하는 절대 위치로 이동한다.

따라서 PID 출력도 **절대 PWM 값**이어야 자연스럽다 → **위치형 PID**.

### 6.2 수식

```
PWM(t) = center_us + Kp·e(t) + Ki·∫e(τ)dτ + Kd·de(t)/dt
            ①           ②          ③             ④
```

### 6.3 각 항의 의미

**① center_us (기준값)**

- 초기 서보 위치 (x=1530µs, y=1300µs).
- "대략 이 근처가 에러=0에 해당하는 PWM"이라는 추정치.
- 정확하지 않아도 됨 → ③ Ki가 보정.

**② P항: `Kp · e(t)`**

- 오차에 **비례**해서 즉시 이동.
- `Kp = 0.5`일 때: 오차 100px → +50µs, 오차 10px → +5µs.
- **역할**: "픽셀 오차 → µs 변환 계수". 클수록 민감, 너무 크면 오버슈트.

**③ I항: `Ki · ∫e(τ)dτ`**

- 오차의 **시간 누적**. 매 틱(20ms)마다 `integral += error × dt`로 쌓인다.
- **역할**: center_us가 실제 "에러=0 PWM"과 다를 때, 그 차이를 **천천히 보정**.
- 예) 실제로 에러=0인 PWM이 1535인데 center=1530이면,
  Kp만으로는 항상 약간의 오차가 남는다(정상상태 오차).
  Ki가 시간에 걸쳐 이 5µs 차이를 메워준다.
- anti-windup: `±2000`으로 클램프해서 적분 폭주 방지.

**④ D항: `Kd · de(t)/dt`**

- 오차의 **변화 속도**에 반응.
- 오차가 빠르게 줄어들고 있으면(수렴 중) → 브레이크를 걸어 오버슈트 방지.
- 오차가 갑자기 커지면(외란) → 빠르게 가속.

### 6.4 숫자 예시 (Kp=0.5, Ki=0.05, Kd=0.01, center=1530)

```text
틱   e_u(px)  P항     I항(누적)  D항      PWM_x(µs)  설명
───────────────────────────────────────────────────────────
 0    100     +50.0   +0.10     +0.0     1580.1      큰 오차 → 크게 이동
 1     60     +30.0   +0.16     −10.0    1550.2      오차 줄며 D 브레이크
 2     30     +15.0   +0.19     −7.5     1537.7
 3     10     +5.0    +0.20     −5.0     1530.2      오차 작아짐
 4      5     +2.5    +0.21     −1.25    1531.5
 ...
50      1     +0.5    +0.30     ~0       1530.8      I항이 서서히 보정 중
100     0     +0.0    +0.35     ~0       1530.4      에러=0 도달
```

### 6.5 center_us가 틀려도 되는 이유

만약 에러=0인 실제 PWM이 1540인데 center=1530으로 설정했다면:

```text
Kp만 있을 때:
  e=0 → PWM = 1530 + 0 = 1530  (실제는 1540이어야 함)
  → 레이저가 10µs분 만큼 항상 어긋남 → 정상상태 오차 발생

Ki를 추가하면:
  e가 0이 아닌 동안 integral이 계속 쌓임
  → 충분한 시간 후 Ki·integral ≈ 10  (1540−1530 보정분)
  → PWM = 1530 + 0 + 10 + 0 = 1540  → 에러=0 도달!
```

### 6.6 Kp 부호와 축 방향

| 축 | 기본 Kp 부호 | 이유 |
|----|-------------|------|
| X (pan) | **양수** (+0.5) | `e_u>0` → 레이저가 왼쪽 → PWM 증가 → 서보 오른쪽 |
| Y (tilt) | **음수** (−0.5) | `e_v>0` → 레이저가 위 → 서보가 아래로 가야 → PWM 감소 |

Y축의 부호는 서보 장착 방향에 따라 다를 수 있다. 실제 구동 시 반대로
움직이면 부호를 뒤집으면 된다.

## 7. 게인 튜닝

- `PID_control/auto_tune_pid.py` 는 **로그 기반** 튜닝용.
- 라즈베리에서는 **실시간 오차**를 받으므로, `--kp-x`, `--kp-y`, `--ki-*`, `--kd-*` 를 바꿔가며 바로 동작을 보면서 튜닝 가능.
- Y축은 보통 **kp-y 음수** (방향 convention). 예: `--kp-y -0.5`.

### 권장 시작값

```bash
sudo python3 pid_pwm_agent.py --host 10.42.0.1 --port 5555 \
  --kp-x 0.5  --ki-x 0.05 \
  --kp-y -0.5 --ki-y -0.05
```

| 게인 | 효과 | 너무 크면 | 너무 작으면 |
|------|------|-----------|-------------|
| Kp | 즉각 반응 속도 | 오버슈트/진동 | 느린 반응, 정상상태 오차 |
| Ki | 정상상태 오차 제거 | 적분 windup, 느린 진동 | 오프셋 남음 |
| Kd | 오버슈트 억제 | 노이즈 증폭, 떨림 | 오버슈트 |

---

## 8. 트러블슈팅

- **Connection refused**: 노트북에서 `ubuntu_tcp_server` 가 먼저 떠 있는지, 방화벽에서 5555 허용인지 확인.
- **PWM 쓰기 실패**: `sudo`로 실행했는지, `config.txt` 적용 후 재부팅했는지 확인.
- **오차가 0으로만 옴**: 호스트 파이프라인에서 실제로 `EX=...,EY=...` 가 전송되는지, 터미널 수동 입력으로 먼저 확인.
- **레이저가 반대로 움직임**: Kp 부호가 반대임. `--kp-x`나 `--kp-y`의 부호를 뒤집을 것.
- **따라가다 멈춤 (정상상태 오차)**: Ki가 0이거나 너무 작음. `--ki-x 0.05` 등으로 키울 것.
- **진동/떨림**: Kp가 너무 크거나 Kd가 부족. Kp를 줄이고 Kd를 추가할 것.
