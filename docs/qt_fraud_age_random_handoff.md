# Qt 전달용: 서버 부정승차 연령값(`age`) 가중 랜덤 변경 안내

최종 갱신: 2026-03-27

## 1) 목적

- 기존 `FRAUD|...` 알림 포맷은 유지
- 서버가 보내는 `FRAUD` 메시지의 `age` 필드 의미 변경을 Qt 담당자에게 전달
- Qt 클라이언트 코드 수정 범위를 빠르게 식별할 수 있게 현재 전제와 영향 지점을 정리
- 최종 UI 문구, 연령 표시 방식, 통계 표 구성은 Qt 담당자 결정 사항으로 남김

## 2) 변경 요약

- 유지:
  - wire format 자체는 유지
  - `FRAUD|<object_id>|<card_age_text>|<age>|<Y|N>|...|TAG=...`
- 변경:
  - 4번째 토큰 `age`의 의미만 바뀜

이전:
- 서버가 `age`에 사실상 고정값 `"20"`을 보내는 구조에 가까웠음

이후:
- 서버가 `10` 이상 `70` 이하의 숫자 문자열을 보냄
- 예시: `17`, `23`, `41`, `63`, `70`

분포 특성:
- `20~45` 구간이 가장 높은 확률로 등장
- `60~70` 구간이 그다음 확률로 더 자주 등장
- `10~19`, `46~59` 구간도 등장하지만 상대적으로 덜 자주 등장

중요:
- `age`는 더 이상 `"20"` 고정값이나 `"30s"`, `"Senior"` 같은 연령대 라벨을 보장하지 않음
- Qt는 `age`를 숫자 문자열로 파싱 가능한 입력으로 받아야 함
- 분포는 균등 랜덤이 아님

## 3) 서버 송신 포맷

형식:

```text
FRAUD|<object_id>|<card_age_text>|<age>|<Y|N>|L=...|T=...|R=...|B=...|X=...|Y=...|TAG=<iso8601>
```

예시:

```text
FRAUD|423219|Adult|23|N|L=12.3|T=45.6|R=78.9|B=101.1|X=50.0|Y=60.0|TAG=2026-03-27T10:11:12.123Z
FRAUD|423220|Senior|64|N|L=10.0|T=40.0|R=80.0|B=120.0|X=45.0|Y=59.0|TAG=2026-03-27T10:11:13.123Z
FRAUD|423221|Youth|17|N|L=15.0|T=42.0|R=74.0|B=109.0|X=44.5|Y=58.0|TAG=2026-03-27T10:11:14.123Z
FRAUD|423222|Adult|70|Y|L=18.0|T=39.0|R=82.0|B=118.0|X=50.0|Y=57.0|TAG=2026-03-27T10:11:15.123Z
```

필드 의미:
- `object_id`: 서버 객체 ID
- `card_age_text`: RFID 카드 기준 연령 카테고리 문자열
- `age`: 서버가 보낸 숫자 문자열 연령값
- `Y|N`: 최종 부정승차 판정
- `TAG`: 서버 이벤트 시각

Qt가 기대하면 안 되는 것:
- uniform random 분포
- 특정 decade 문자열 포맷 고정(`20s`, `30s`)
- 특정 연령대 라벨 포맷 고정(`Senior`, `Adult`)

## 4) 현재 Qt 코드 기준 영향 범위

아래는 현재 Qt 코드 전제를 정리한 것이며, 구현 방향 자체를 강제하는 문서는 아님.

### 4-1. 수신 계층

- `FraudManager`는 `FRAUD` 라인의 4번째 토큰을 `age` 문자열로 그대로 파싱해 downstream으로 전달 중
- 현재는 숫자 문자열 자체를 막지는 않음

참고 파일:
- `client/src/fraudmanager.cpp`

### 4-2. 모니터링/상세 표시 계층

- `MonitoringView`는 현재 속성명을 `ageGroup`으로 사용하고, `"Age Group: ..."` 형태 문구를 생성 중
- `DetailView`도 `ageGroup` 기반 표시를 사용 중
- 즉 현재 UI 문구와 속성명은 `"30s"` 같은 연령대 문자열을 기대하는 쪽에 더 가까움

참고 파일:
- `client/src/views/MonitoringView.qml`
- `client/src/views/DetailView.qml`

### 4-3. 통계 집계 계층

- `AnalyticsView`는 `ageGroup` 문자열 안에 `"10"`, `"20"`, `"30"`이 포함되는지 확인해 막대 카운트를 올리는 구조
- 숫자 age 도입 후에도 substring 방식만 유지하면 집계 의미가 불명확해질 수 있음
- 통계 화면은 숫자 범위 기반 집계로 바꾸는 작업이 필요함

참고 파일:
- `client/src/views/AnalyticsView.qml`

## 5) Qt 담당자 작업 포인트

### 5-1. 필수 수신 처리

- `age`를 숫자 문자열 기준으로 안전하게 파싱
- 파싱 실패 시 fallback 또는 예외 처리 정책 정의
- 음수, 빈 문자열, 범위 외 값이 들어왔을 때의 UI/로그 처리 기준 정의

### 5-2. 표시 방식 결정

아래는 Qt 담당자 결정 사항:
- raw 숫자 age를 그대로 표시할지
- raw age를 내부에서 버킷으로 변환해 표시할지
- raw 숫자와 버킷을 함께 보여줄지

이 문서는 위 표시 정책을 고정하지 않음.

### 5-3. 통계 집계 처리

- substring 매칭 기반 집계는 숫자 age 도입 후 유지하지 않는 것을 권장
- 숫자 파싱 후 범위 기반으로 통계 표/막대 집계를 구성하는 쪽이 적합
- 버킷 기준 자체는 Qt 담당자 결정 사항

### 5-4. 테스트 전제

- 테스트 시 uniform random을 가정하지 말 것
- `20~45`가 가장 자주 들어오고, `60~70`이 그다음으로 비교적 자주 들어온다는 전제를 반영할 것
- 특정 한두 값만 반복되는 입력을 정상 분포로 간주하지 말 것

## 6) 비범위 / 책임 구분

- 이 문서는 Qt 수신 계약과 영향 범위 전달용 문서임
- 클라이언트 최종 UX 문구는 Qt 담당자 책임 범위
- 통계 표 레이블, 버킷 기준, 상세 화면 표현 방식은 Qt 담당자 결정 사항
- 서버 쪽 가중치 상수의 정확한 수치 비율은 이 문서의 범위에 포함하지 않음
- Qt는 `age`의 범위와 비균등 분포만 전제로 처리하면 충분함

## 7) Qt 검증 체크리스트

1. `age`가 숫자 문자열일 때 파싱이 깨지지 않는지
2. `17`, `23`, `45`, `60`, `70` 같은 경계/대표값 입력으로 표시가 정상인지
3. 모니터링/상세 화면에서 숫자 age 유입 시 비정상 문구가 생기지 않는지
4. 통계 화면이 기존 substring 매칭 전제에 묶여 있지 않도록 수정 대상이 식별되는지
5. 비균등 분포에서도 특정 값 또는 특정 포맷만 전제로 UI가 구성되지 않는지
6. `card_age_text`와 `age`가 서로 다른 형식이어도 표시/집계가 혼동되지 않는지

## 8) 한 줄 정리

- Qt는 앞으로 `FRAUD` 메시지의 `age`를 연령대 라벨이 아니라 숫자 문자열 입력으로 받아야 하며, 표시와 통계 집계는 Qt 쪽에서 별도 정책을 정해 처리해야 한다.
